# "ai" group: drivers, AI behaviours, race rules, activities, MXGame::Update

Owner: wave-2 agent "ai" (2026-10-18). Ranges: 0x00500000..0x0053ffff (BaseDriver / RaceDriver / FreeRideDriver / NetworkDriver,
Behavior* and Rule* classes), 0x00550000..0x0058ffff (Activity, MXActivityRace / RaceStub / FreeRide, ActivityAudioLogic),
0x007f0000..0x007fffff (Behavior* vfuncs, icon properties), 0x00890000..0x008affff (BehaviorPerformStunt, BehaviorSeperate vf5, ...),
0x00460000..0x0047ffff (RavenVehicleMotocross vfuncs that are not in physics-functions.tsv) and 0x00750000..0x0075ffff
(MXGame::Update, MXGame_PlayerMode, TutorialManager_Outcome, ...). Work list: the functions of `plan/nonphysics.tsv` in these
ranges minus `plan/physics-functions.tsv` (347 functions, 739,417 instructions per frame summed over the plan's worlds).

## What is ported

337 of the 347 functions, 739,372 of the 739,417 instructions per frame. Left original:
- the two GetCurrentThreadId import thunks, 008a0500 `jmp 0x8aebc0` and 008aebc0 `jmp [IAT]` (the stand-in keeps seeing the import);
- eight functions that never run on the five verify worlds (0 to 2 instructions per frame in the plan), so they could not be
  verified: 0055e820 Activity::vf12, 00525cd0, 0055dc20, 00567660, 007f1810, 00565640 MXActivityRace::vf52, 00582d50
  RaceActivityAudioLogic::vf32, 007520a0 TutorialManager_Outcome. They generate and compile like the others (remove them from
  `ai_tools/skip.txt` and regenerate) once a world exercises them (race end, tutorials). Files: `ports/ai_gen_46.cpp`, `ai_gen_50.cpp`,
`ai_gen_52.cpp`, `ai_gen_55.cpp`, `ai_gen_75.cpp`, `ai_gen_7f.cpp`, `ai_gen_89.cpp` (one per address range), helpers in
`ports/ai_util.h`.

They are instruction-level transliterations generated by the scratchpad's `ai_tools/gen.py` (an adaptation of the world agent's
`rider_tools/gen.py`): one C++ statement per original instruction with the instruction in the comment, guest registers in locals,
the stack frame literally on the guest stack, flags only where a consumer reads them (fused cmp/test/comiss + jcc), x87 through
reflex_f80 as vm.cpp executes it, and every call (direct, virtual, IAT) made through `Machine::call_function` to the same target in
the same order. So the AI's CRT `rand()` (`call [0x91624c]`, e.g. in 0050fef0) is
the same call in the same order, and the stand-ins (heap, FMOD, input, worker SetEvent switches) see identical import calls.
Outputs declared: EAX / ECX / EDX / all xmm / x87 (AI_OUTS), since LTCG conventions here pass results in xmm0 and registers.

Regenerate: `ai_tools/genall.py` (reads `ai_list.tsv`, `ai_tools/skip.txt`, optional `names.txt` / `inline.txt`), then
`REFLEX_PORT_FILES="math*.cpp ai_*.cpp" tools/build_cli.sh <out>`.

## Generator additions over rider_tools/gen.py

- `fs:` operands (SEH frames: `mov eax, fs:[0]` ... `mov fs:[0], eax`) as `AI_FS_BASE` (0x7ffd0000, the world runtime's TEB). The
  natives link and unlink SEH records exactly as the original; no exception is ever raised through a native (a C++ throw would not
  unwind native frames: `_CxxThrowException` sites exist in 00502e30 / 005035c0 but are std::vector length errors that never fire).
- `movq`, `pxor`, the x87 integer arithmetic forms (fiadd / fimul / fidiv / ...), fcomi / fcomip / fucomi / fucomip (vm.cpp sets
  only CF / PF / ZF and keeps the other flags), fcom family into the status word, `fnstsw` (with TOP, as vm.cpp), `sahf`.
- Return-address slots: `Machine::call_function` pushes 0 as the callee's return address (the run stops there). After the call
  `AI_CALL(target, ra)` writes the original's return address into that slot (if the callee left it 0), and `AI_TAILJMP` does the
  same for its slot. Without this, Verify of MXGame::Update on SX_Springfield_ai11 showed `[00d99ee0] 0 orig 0055e527` and
  `[7fbffec0] ...`: code running on a worker stack (0x7fbfxxxx, not the main thread's dead stack, so Verify compares it) left the
  return addresses of 0055e360's calls there, and something copies that region to 0x00d99ee0. With the real return addresses the
  dead stack is the original's byte for byte.

## Verification

- `tools/verify.sh <boot> ai`: 0 mismatches and "on: identical" on all five worlds (see the report). Verify only checks the
  outermost port of a call tree (nested ports run natively inside it), so MXGame::Update's 0 mismatches cover everything below it.
- Depth check (`ai_tools/peel.py`): repeats Verify with the outermost ports of the previous round excluded, so every layer of
  callees becomes outermost in turn and each port is verified on its own. 2026-10-18: 11 rounds on the five worlds, every one of
  the 337 ported functions verified as outermost with 0 mismatches (layers: 10, 23, 17, 7, 33, 29, 58, 94, 54, 12 ports).
- Since the lead's 2026-10-18 change (Verify snapshots the emulator's host state: heap bookkeeping, QPC, audio capture, worker
  switches ...) ports whose call trees allocate or free (Activity vf23 / vf24 / vf25, MXActivityRaceStub vf23, 0055f700, ...) verify
  normally. Before it they reported 0x3000xxxx heap pointer differences and "HeapFree of an unknown block" stops.

## Traps

- min / max with a NaN operand return the source operand unquieted (Intel SDM); ai_util.h's sse32 / sse64 have the lead's fix
  (2026-10-18, matching vm.cpp). The final verify runs are on that build.

- Python: a script named `bisect.py` next to `gen.py` shadows the stdlib module that capstone / pefile import; the generator then ran
  it. Keep tool names unique (`ai_bisect.py`).
- The plan's names are Ghidra's; 0x00755d30 is Thomas Wang's 32-bit integer hash (`_re/names/9e_ai.tsv`).
- The transliterations keep the original memory layout and calling conventions on purpose; turning them into readable C++ (driver /
  behaviour / rule classes) is the next step, function by function, against these exact versions.
