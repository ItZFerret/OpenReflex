# ld_inflate (0x8e0000..0x900000): zlib 1.2.3, the LZX decoder, CRT helpers

Wave 4 (native loading), 2026-10-18. Files: `ports/ld_inflate.cpp` (67 ports, captured backend), `ports/ld_inflate_fl.cpp`
(3 ports, fl backend: `_RTC_CheckStackVars` uses `leave`, `__RTC_CheckEsp` reads the caller's flags at entry, 008f9d30 has a
narrow shift whose flags are read). All generated by `tools/lift/gen.py --list` (lists in the scratchpad: ldg/inflate_cap.tsv,
ldg/inflate_fl.tsv); regenerate rather than edit.

## What the functions are

- zlib 1.2.3, built with `/RTCs` (every call is followed by `cmp esi, esp; call __RTC_CheckEsp`, frames are filled with
  0xcccccccc and checked by `_RTC_CheckStackVars`): `zlib_inflate` 008ea630, `zlib_inflate_fast` 008ef330, `zlib_inflate_table`
  008efd70, `zlib_fixedtables` 008ec4e0, `zlib_adler32` 008f04c0, `zlib_zcalloc` 008ef290 / `zlib_zcfree` 008ef2f0 (names in
  `_re/names/9e_ld_inflate.tsv`). 008ea380 / 008ea460 / 008ea5e0 / 008ec530 / 008ec710 look like inflateReset / inflateInit2_ /
  inflateInit_ / updatewindow / inflateEnd but are left Fn_ (not proven).
- The LZX decoder (release build, no RTC; roles read from the code, not proven): 008f6e30 (the block loop: reads the block header,
  calls the table builders and block decoders), 008f90b0 (a block decoder: main tree with a 10-bit fast table, repeated-offset
  queue at +0xc..+0x14, window mask at +8; 4.95 G of the boot's instructions alone), 008f8a80 / 008f87c0 / 008f8d70 (other block
  decoders / tree reads), 008f9a30 (builds a Huffman decode table from bit lengths: the only user of
  `shr ecx, 1; rep stosd; adc ecx, ecx; rep stosw`), 008f94a0 / 008f9920 / 008f99e0 / 008f9d30 (pre-tree / tree reads).
- CRT: `__SEH_prolog4` / `__SEH_epilog4`, `__onexit` / `_atexit`, `_RTC_CheckStackVars`, `__RTC_CheckEsp`.

## Traps (lifter extensions, see tools/lift/README.md)

- **`__RTC_CheckEsp` reads the caller's ZF.** The captured backend only computed flags where a consumer in the same function reads
  them, so a lifted zlib function handed stale `fl` to the check, which then reported an ESP failure (`_RTC_Failure` ->
  RaiseException 406d1388, the boot stopped at frame 0). Fixed in both backends (`FLAGS_IN`): the call is a ZF consumer and the
  EFLAGS word (fl_sub ... of the `cmp esi, esp`) is materialized into `fl` before `LIFT_CALL`. Any port of /RTCs code needs this
  (callers of 008fa3bd: 008ea460..008f4710, see functions.tsv).
- **`__SEH_prolog4` reuses its return-address slot** for the EH4 record's encoded scope table ([ebp-8]); LIFT_CALL's write-back of
  the return address would overwrite it (`NO_RA`). Only `__onexit` calls it in these groups.
- `__SEH_prolog4` returns with ESP below its entry: its port declares `OUT_ESP_BELOW` (hand edit of the generated signature in
  ld_inflate.cpp: re-apply it after a regeneration), else the per-call Verify in the boot runs the original past the return and
  reports "the original would switch threads".
- Shift flags (CF / OF of an immediate-count 32-bit shift) are now modelled (008f9a30's `adc ecx, ecx` reads the CF of `shr ecx, 1`).

## Left unported

- `__get_sse2_info` 008fa708: `pushfd` / `popfd` EFLAGS.ID probe and `cpuid` (runs once at startup, 43 instructions).
- `__aullrem` 008fa310: `rcr` chain (64-bit unsigned remainder; 14 instructions in the boot).
- The import thunks (`*.DLL::*`, 6 bytes `jmp [IAT]`): not ported by design.

## Results

- With the per-call Verify in the boot (loading_accept.sh VERIFY=1, together with ld_game): 0 mismatches.
- loading_accept.sh ld_inflate, Concord and Alpine: canonical dump IDENTICAL, world images 0 pages differ, race IDENTICAL, race
  hashes identical. The ports are not called in race frames.
- Boot time (baton boot of Concord, CPU user time, one machine shared with other agents, two runs each): original 17.5 / 18.3 s,
  REFLEX_PORT=ld_inflate 13.0 / 12.7 s (-28 %). The lifted hot loops still go through `m.mem.read/write` per access (bounds +
  page lookup), which is what is left of the cost; a host zlib / lzxd would only be allowed with bit-identical output and the
  same allocations (notes/loading.md).
