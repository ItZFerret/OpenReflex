## How the ports are made: the bike lifter

Every port is an instruction-level transliteration generated by a copy of the bike group's lifter (notes/bike.md), extended for
this range: `scratchpad/fxag/lift/lift.py` + `gen_all.py` (list `fx_list.tsv`, skips `skip.txt`, optional `names.tsv`).
Regenerate: `cd scratchpad/fxag/lift && _re/.venv/bin/python gen_all.py`. Registers are locals, the stack frame stays in guest
memory, every call goes through `FX_CALL` (registers synced, the original return address rewritten into the slot afterwards), all
registers are reproduced. Declared outputs follow the lead's outputs rule (2026-10-18): `outs.py` computes, per function, the
volatile registers live at every direct call / tail-jump site (liveness over the caller's CFG; a following direct call uses its
callee's live-in registers, a `ret` the caller's own outputs, recursively; callees whose CFG walk fails get a straight-line live-in
plus ECX / EAX / EDX), x87 st(0) when the first x87 instruction after a site consumes it, and EAX + x87 for address-taken functions
(vtables, job pointers: standard conventions). Each port's header comment gives the register inputs (abi.py). Because the frame and the return-address slots are the original's, the dead
stack below ESP is the original's too (no DeadStack cases needed; the particle spawners copy stack templates with unwritten lanes,
see notes/dead-stack.md: 128-byte particle records at 0x1428xxxx are the particle arrays).

`fx_util.h` is a copy of `bike_util.h` (namespace `fx`, `FX_*` macros) so this group does not depend on another group's header
(not regenerated by gen_all; the lead patched its sse32 / sse64 min / max to the Intel rule, 2026-10-18: MIN/MAX return the source
operand when either is NaN, unquieted, as vm.cpp now does), plus:
- `rcpss / rcpps / rsqrtss / rsqrtps` with the reference's tables (`rsqrt_rcp_tables.inc`, the same functions as vm.cpp rsqrt32 /
  rcp32). Particle_UpdateJob uses both (1 / life, the drag factor).
- `FS_BASE` (0x7ffd0000, the world runtime's TEB): `fs:` operands (Particle_UpdateJob writes the job pointer / index into the
  thread's static TLS block, fs:[0x2c]; SEH frames write fs:[0]).
Lifter additions: fs: segment, rcp/rsqrt, `fnstcw / fldcw` (the truncating fistp sequences of the colour curves), `div / idiv`
(the reference's #DE cases throw), `lock cmpxchg` (flags as `cmp eax, dst`), `sbb r, r` whose carry a second `sbb` reads
(`sbb eax, eax; sbb eax, -1` after the inlined strcmp loops), MMX `movq mm` / `cvtpi2ps` / `emms` with the reference's mmx_active
rules (0041c580), `movq xmm`, `int3` after noreturn calls (throws), and a fix of the generic flag builder (it evaluated every
condition, so an unavailable flag (None) crashed even when it was not the one asked for).

## Particles

- Particle_UpdateJob 006925f0 (4.2M instructions per frame, 71% of the group): a job of the engine job pool (cdecl, one argument:
  {+0 manager, +4 count, +8 asset data, +0x10 time, +0x14 dt}). The world runtime serializes worker threads (a SetEvent runs the worker job to
  completion), so the shared index (manager +0xbc, InterlockedIncrement) is consumed by the first of the two jobs; the second finds
  nothing, and the last one (InterlockedDecrement of +0xc4 reaching 0) compacts dead particles (dead list +0xb4 / +0xb8, Particle_Copy)
  and releases the spin lock +0xc8 (InterlockedCompareExchange; Sleep(0) would throw in the runtime). The Interlocked* calls go through
  the IAT (0x916080 / 0x916084 / 0x91609c) to the stand-ins, as the original. x87 part: `_copysign` (CRT, via 0x916230) + 008fa0d0
  (math group) round the curve index; the colour channels are `fld / fmul / fadd / fistp qword` under a truncating control word on the
  worker's own x87 state.
- Particle_Copy 00692b50: fastcall-like (ECX src, EAX dst), copies through x87 `fld / fstp` (SNaNs come out quieted, as in the
  original), the 8-byte +0x68 field through `fld qword`.
- The particle simulation shares the CRT rand() with gameplay: every rand call is an FX_CALL in the original order.

## Traps

- Verify with `math,fx` (before the lead's 2026-10-18 fix of the compare) reported mismatches in ParticleEntity::UpdateManagers
  006960c0 and 00691bd0 on addresses 0x7fbfxxxx: the worker stacks (WORKER_STACK_TOP 0x7fc00000). The particle jobs run there
  (serialized worker switch inside the verified call), and the math ports 008fa0d0 / 008fa106 / 0042c230 nested in them do not
  reproduce their dead stack; that stack was not below the verified call's ESP, so the compare counted it. Excluding those three
  math ports gave 0 mismatches. Verify now leaves out stacks the verified call does not run on.

- Verify needs the lead's host-state snapshot (2026-10-18): before it, any port whose call tree allocated (00419cd0 / 00418800 /
  004175e0: std::vector growth with ReflexAlignedAlloc -> msvcr90 _aligned_malloc -> HeapAlloc) mismatched (the native's block was not
  rolled back) and the world stopped on "HeapFree of an unknown block".
- 00418470 (std::vector<0xb0-byte record>::_Insert) has an SEH frame and a catch funclet at 004186d5 (`Catch@004186d5` in
  functions.tsv is the funclet: it shows as executed only because the plan attributes 00418470's own instructions in that address
  range to it). The port of 00418470 is correct as long as nothing throws through it; a C++ exception unwinding through a native frame
  would not work (the CRT would resume the original code inside the nested run). No throw happens in the test worlds.
- Many entries here are tiny shared vfuncs (`ret`, `mov eax, imm; ret`, ...) and rtti_shared functions; they are ported at their
  address, which covers every class that uses them.
