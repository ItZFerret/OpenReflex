## The spin site 005dbe50

Fn_005dbe50 (called by UIManager::vf30 005daca0 in `do done = f(last DefaultPackages package) while (!done)`) is ported like
any other function. The boot's spin-site native (boot.cpp) stays at the address: it yields, then falls through to the port
(`reflex_port::installed`). UIManager::vf30 is ported too; its LIFT_CALL(0x5dbe50) goes through Machine::call_function -> run, so
the native (yield) still runs on every iteration: verified by the boot completing (a missing yield hangs the boot at
MXUI.dx9.package, notes/loading.md).

## Trap found: jumps into Ghidra "functions" that are labels

Ghidra starts functions at labels inside a function (the continuation after an SEH catch funclet, e.g. 005e3c8f inside
005e3b60, `catch (...) { ...; throw; }` in STL-like vector code). The first lift (before the shared lifter's stack-depth check
landed) emitted LIFT_TAILJMP for `jmp 005e3c8f` with the frame still on the stack: boots died with "execution outside mapped code
bfa0xxxx" (bisected to the 005e32d0..005e3f00 cluster). The current lifter (walk(): internal_jmps) lifts such jumps inline;
ld_ui_5e.cpp was regenerated with it (29 -> 6 LIFT_TAILJMP).
