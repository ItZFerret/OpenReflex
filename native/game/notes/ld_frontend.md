## Left unported

- **005a7f10 SavedGameManager_ThreadProc** (229 instructions, the saved-game manager thread). Under baton the thread is
  blocked inside the proc's WaitForSingleObject (`MXUISavedGameManager::EndEvent`) when the world image is written. A lifted
  port makes that call with LIFT_CALL, which keeps 0 in the return-address slot while the callee runs, so the image has 0 at
  the waiting thread's ESP (132fffcc; the original has 005a7f31) and a resumed image (front end, saved games) would return to
  0. The canonical dump does not see it (stacks), the image diff does (1 word). General rule for every group: **a function
  that is on a guest thread's call stack while that thread is blocked at world capture must stay original** (or the shared
  LIFT_CALL needs a way to keep the original return address in the slot), unless only the main thread's frame-stop path is
  involved.
  The thread's other functions (SavedGameManager_Process 005a76c0 etc.) return before the capture and are ported.
