Exporting bike skins as .rxmod

Everything a skin tool needs to output a livery the game loads as one file: what a skin can paint, the mod.json it carries, the picture rules, the byte layout, working writers in Python and C#, a sample, and how to test.

RxModSkinWriter.cs C# skin writer, no packages (needs RxTrackWriter.cs) rxmod.py Python reference: check, pack, list, extract, token, new-skin sample/ a working skin: the folder, the .rxmod and the C# that wrote it

The tools also live in the OpenReflex repo under tools/rxmod/ and tools/rxtrack/; the full format spec is core/plan/RXMOD.md.

Start here

A skin is a small .rxmod file that repaints a bike: it holds your pictures and a mod.json that says which bike they paint and which of its textures they replace. It never touches the bike's model or physics. Players drop it into Mods/Bikes (any sub-folder) and the skin shows up in GARAGE > VEHICLE as a card of its own, tagged MOD and credited BY <author>.

Under the hood a .rxmod is the same RXAR container as a .rxtrack (a 64-byte header, the files' bytes, an index), with the kind MODS. Your tool produces the pictures; packing them is the last step, and there are three ways to do it:

Easiest

Call the reference tool

Write a folder (mod.json + pictures), then python3 rxmod.py pack <folder> out.rxmod. Standard library only.

Built-in

Use the C# writer

Drop RxModSkinWriter.cs + RxTrackWriter.cs into a .NET / Unity tool: it writes the mod.json, checks the pictures and packs the file in one call.

Any language

Write it yourself

The container is ~60 lines (see write_archive in rxtrack.py). Stored entries need no zstd library.

Tested against the game.The sample in sample/ was written by RxModSkinWriter.cs and loaded in the experimental build: both of its skins show as garage cards and paint their bikes (pictures below). Its content id from C# (02ccc6c709f9) is the one rxmod.py token and the game compute.
Which builds read it.Skins load in the experimental OpenReflex builds (commit 1590cc7c and later; .rxmod bikes since 466458c8). The released 1.0.x line doesn't read .rxmod yet.

What you can paint

One skin per bike, per file

The rule your exporter must enforce.A skin file holds at most one skin per original bike it ends up on: the garage stores the player's choice per (file, VehicleModelId). A .rxmod bike counts as the original it rides as: the YZ250F is #31, so {"original": 31} and {"mod": "nfgcole-2023-yamaha-yz-f", "bike": "yz250f"} in one file collide and the game drops the second (its log says so). Several liveries for one bike = several files.

mod.json

At the archive's root. UTF-8 JSON:

{
  "format": "reflex-mod", "version": 1, "type": "skins",
  "name": "Monster Energy Pack", "author": "Your Name", "description": "optional",
  "thumbnail": "preview.png",
  "skins": [
    { "mod": "nfgcole-2023-yamaha-yz-f", "bike": "yz250f", "name": "Monster Energy",
      "maps": { "yz250f/diffuse.png": "skin0/diffuse.png" } },
    { "mod": "nfgcole-2024-kawasaki-kx", "bike": "kx450", "name": "Pink Body",
      "materials": { "body": { "diffuse": "skin1/body.png", "spec": "skin1/body_spec.png" } } },
    { "original": 31, "name": "Blue Takashi",
      "maps": { "plastics": "skin2/plastics.png", "seat": "skin2/seat.png" } }
  ]
}
FieldRule
format, version, type"reflex-mod", 1, "skins". Required.
name, authorThe pack's name and its author. Author required: every card says BY <author>.
description, thumbnailOptional; the thumbnail is a picture in the archive.
skins[].mod + skins[].bikeA .rxmod bike: the mod's id / name; the bike's id / model / brand + model / VehicleModelId. "bike" may be a list (one skin per entry, one per bike); empty = the mod's only bike.
skins[].originalAn original bike's VehicleModelId (instead of mod / bike).
skins[].nameThe skin's name on its card.
skins[].maps{key: entry}. .rxmod bike: the key is one of the bike mod's map entries (every material using it takes yours). Original: a role or a texture name.
skins[].materials.rxmod bikes only: {material: {diffuse, spec, normal, sfx, template, mud, shine}}; what you leave out stays the bike's.
skins[].logoOptional brand logo picture for the garage stage.

Every entry a field names must be in the archive. A skin that replaces nothing, names no bike, or names a bike mod the player hasn't installed is left out (and logged); the rest of the file still loads.

The pictures

  • PNG or JPG, 8 bits per channel (RGB or RGBA).
  • Sides are powers of two, at most 4096 (2048 x 1024, 4096 x 4096 ...). Any size works for any target (UVs are 0..1); match the template for full detail.
  • Same orientation as the template: paint on the template picture as it is, export it the same way up. No flipping.
  • Colours are used as stored (no colour-space conversion, like the game's own textures): what you see in the picture is what goes on the bike.
  • Alpha is ignored on painted surfaces (plastics, frame ...); it only cuts holes in materials made for it (TM's wheels).
MapWhat it does
diffuseThe colours and graphics. This is the skin.
specGreyscale (its luminance): how shiny / reflective each spot is. The game builds the shader's SFX map from it.
normalTangent-space normal map (tyres only). Green up; "normalFlipY": true for DirectX-style maps.
sfxAdvanced: the shader's own SFX map instead of one made from spec: R = shine, G = where mud builds up (0..1, half = an even coat), B = reflection.

The game uploads each picture with mipmaps and GPU block compression at load, so file size is a download concern only: a 4096 atlas PNG is typically 3-15 MB, a 2048 one 1-4 MB; JPG (quality 90+) is fine for diffuse maps.

The file format

An .rxmod is an RXAR container exactly as described in the track archive guide (Reflex Track Archives Guide.html of the rxtrack kit, or core/plan/RXARCHIVE.md), with three differences:

.rxtrackskin .rxmod
Header kind (offset 8, u32 LE)TRAK = 0x4B415254MODS = 0x53444F4D (the bytes 4D 4F 44 53)
FilesDatabase/<stem>.dx9.*, Mod/*mod.json at the root; pictures at any paths it names (the writers use skinN/)
Index metadata JSONthe track's{"format":"reflex-mod","type":"skins","name":...,"author":...}

Everything else is shared: the 64-byte header (magic RXAR, container version 2, the index offset / sizes / CRCs), entries stored (codec 0; PNG / JPG don't compress further) or zstd, a SHA-256 per entry, equal bytes stored once, the index as one zstd frame (a frame of raw blocks is valid: no zstd library needed). Paths: relative, /-separated, no . / .. / empty component, no \, : or control bytes, at most 1023 bytes, unique ignoring ASCII case. The writer writes <out>.partial and renames it last.

Writing one

Python (reference: rxmod.py)

Write a folder the way the game reads one (the game also loads the folder from Mods/Bikes, handy while iterating), then pack it:

myskin/
  mod.json
  skin0/diffuse.png

python3 rxmod.py check myskin                               # mod.json, every picture's format and size
python3 rxmod.py check myskin --base "2023 Yamaha YZ-F.rxmod"   # + the mod / map names exist in that bike mod
python3 rxmod.py pack  myskin "Monster Energy.rxmod"         # packs what mod.json names (+ .txt / .md readmes)
python3 rxmod.py token "Monster Energy.rxmod"                # the online tokens (s:<content id>:<index>)

rxmod.py imports rxtrack.py (kept beside it in this kit) for the container. pack refuses a folder that doesn't check out.

C# (RxModSkinWriter.cs)

No packages, C# 7.3+, .NET or Unity. Add RxModSkinWriter.cs and RxTrackWriter.cs to your project:

var yz = new RxModSkinWriter.Skin { Mod = "nfgcole-2023-yamaha-yz-f", Bike = "yz250f", Name = "Monster Energy" };
yz.Maps["yz250f/diffuse.png"] = File.ReadAllBytes("yz250f-livery.png");

var tk = new RxModSkinWriter.Skin { Original = 32, Name = "Blue Takashi" };      // (32: not 31, see "One skin per bike")
tk.Maps["plastics"] = File.ReadAllBytes("plastics.png");
tk.Maps["seat"]     = File.ReadAllBytes("seat.png");

var kx = new RxModSkinWriter.Skin { Mod = "nfgcole-2024-kawasaki-kx", Bike = "kx450", Name = "Pink Body" };
kx.Materials["body"] = new Dictionary<string, byte[]> { { "diffuse", File.ReadAllBytes("kx-body.png") } };

string id = RxModSkinWriter.Write(@"C:\Out\Monster Energy.rxmod", "Monster Energy", "Your Name", new[] { yz, tk, kx });
// id: the content id (12 hex); RxModSkinWriter.Check(bytes, what) / Size(bytes) validate a picture up front

Write builds the mod.json, puts every picture under skin<index>/, checks formats and sizes (an InvalidDataException names the bad one), refuses a skin without an author, a target or a map, and returns the content id. sample/SampleProgram.cs is the program that wrote the sample.

Other languages

  1. Collect the entries: mod.json (UTF-8) and every picture, with archive paths following the path rules.
  2. Port write_archive from rxtrack.py (header, stored entries, sorted index with SHA-256, the index as a zstd frame of raw blocks), with kind 0x53444F4D and the skin metadata JSON.
  3. Run rxmod.py check and rxmod.py list on the result, then try it in the game.

Templates

Paint on the picture the skin replaces:

  • A .rxmod bike: python3 rxmod.py new-skin "2023 Yamaha YZ-F.rxmod" myskin --bike YZ250F --name "My livery" --author "Me" copies the bike's diffuse atlas to myskin/skin/ and writes a ready mod.json; or rxmod.py extract the bike mod for all its maps. The bike authors' PSD templates (the NFG COLE pack ships them) are the better source: same layout, with layers.
  • A game bike: tools/rxmod/original_template.py in the OpenReflex repo exports every graphics kit of a chassis from the player's own install as PNG (--list shows the chassis and kits). It needs the repo's readers and an install, so it isn't in this kit: ask for the templates you need. Paint on the HR_..._Plstc_... picture (2048 x 1024).
Credits.A skin is painted over someone else's bike or template: put your name in author, credit the bike's author in your description, follow their terms, and ship only your own art (never the game's textures as they are).

Testing your output

  1. python3 rxmod.py check <file or folder> [--base <bike .rxmod>] ends with ok.
  2. Copy it into <game>/Mods/Bikes/ (the bike's .rxmod must be there too, for a .rxmod bike's skin) and start an experimental build.
  3. GARAGE > VEHICLE > MY RIDES > MODDED BIKES: your card is there (YZ250F · MONSTER ENERGY, BY YOUR NAME); A equips it; the stage shows your paint.
  4. The game's log (Player.log) says what it did with each skin:

Online play

A rider's look carries the skin as a token: "skin": "s:<content id>:<skin index>", next to "bike": "b:<bike mod's content id>:<VehicleModelId>" for a .rxmod bike (alone for an original's skin). The content id is the first 12 hex digits of SHA-256 over the lines path:size:sha256-hex of every entry, sorted by path, joined with \n (RxModSkinWriter.ContentId, rxmod.py token). A rider with the same file sees the skin; a rider with the bike but not the skin sees the bike's own paint; anyone else the original bike. Physics never change. Any byte change gives a new id: a re-export is a new version that the others need too.

Rules checklist

  • mod.json at the root: "format": "reflex-mod", "version": 1, "type": "skins", a name and an author.
  • Every skin names its bike (mod + bike, or original) and replaces at least one map.
  • At most one skin per original bike in a file (a .rxmod bike counts as the original it rides as).
  • Pictures are PNG / JPG, power-of-two sides, at most 4096, painted the same way up as the template.
  • Every entry mod.json names is in the archive; paths follow the path rules.
  • Header kind MODS; index metadata {"format":"reflex-mod","type":"skins",...}.
  • rxmod.py check says ok; the card shows in the garage.
  • No models, no .dx9 files, no physics: a skin is pictures only (whole bikes are "type": "bikes"; classic kit packs "type": "kits" in Mods/Gear).
  • No game textures shipped as they are.

FAQ

Can one file hold skins for several bikes?

Yes: one entry per bike (or "bike": ["kx250", "kx450"]), each its own garage card — just not two on the same original bike.

Do I have to repaint the whole bike?

No. Replace one map, or one material's maps ("materials": {"body": {...}}): everything else stays the bike's.

What about the rider's number?

On the game's bikes the plates keep the rider's run-time number over your paint. On .rxmod bikes the plates are part of the picture: paint a number, or leave them blank.

Can the skin change the shine?

Yes: a spec map (greyscale) per material, or shine (a 0..4 scale of the bike's spec). mud (0..1) sets how much mud a material takes.

Is the folder form OK to ship?

The game loads a folder with a reflex-mod mod.json too, but ship the .rxmod: one file, checksummed, and its online token is stable.

Where's the full spec?

core/plan/RXMOD.md in the OpenReflex repo (sections "Skins" and "Skins of the original bikes"); the container: core/plan/RXARCHIVE.md.
