# Native Windows x64 core

`core/tools/build_windows.sh <out> [Windows zlib prefix]` cross-builds **current native rxcore.dll**, using only core/src, core/game and core/api. No emulator, oracle, capstone, original executable, or reflexworld DLL is linked. MinGW-w64 GCC/G++16.2 is available here. Existing static Windows zlib is under `builds/windows/plugin/deps`; no dependency downloads are required. `RX_BUILD_JOBS=1` is the default and the parent controls build pacing.

The builder preserves exact float flags, disables contraction/fast math, statically links compiler/C++/thread/zlib dependencies, checks explicit API exports, and records PE sections/imports/exports. It keeps source/compiler/flags/header freshness and per-object diagnostics for incremental retries. Target architecture is x86-64 (Unity Windows64); game addresses remain32-bit arena offsets.

Windows runtime support uses an arena-only vectored handler to commit reserved pages on first read/write. Unrelated faults and execution into arena data continue to the session fault guard. The Windows guard catches selected hardware exceptions only on the calling guarded thread and SIGABRT, captures the diagnostic through a temporary stderr descriptor, and restores the game stack on failure. Existing macOS behavior is unchanged.

To avoid resetting runtime-library locks/heap state, the builder uses -fdata-sections and selectively renames only core object .data/.bss (including per-symbol sections) to .rxdata/.rxbss before linking. GCC __emutls control/template sections are excluded because libgcc retains their indices for the process lifetime; the transformer checks symbol section assignments and rejects accidental inclusion. `rx_reset_win.c` snapshots those exact PE sections. `.rxkeep`, TLS and statically linked runtime data are excluded. This section contract is required; missing .rxdata makes capture fail rather than pretending repeat sessions work. .rxbss is optional: current MinGW places zero-initialized core symbols in per-symbol .data sections, so those are captured in .rxdata. Static inspection of all347 produced core objects found six intentionally excluded emutls sections and no other nonempty writable .data/.bss orphan sections.

`core/tools/build_windows_reset_test.sh <out>` builds a tiny standalone EXE with the same section transformation. Run it on Windows: it checks initialized and zero data reset twice, KEEP bookkeeping survives, a live CRT heap allocation survives, and TLS first accessed after capture survives both resets. Targeted MinGW syntax checks passed for the changed runtime sources and fixture; the full DLL compile/link, PE inspection, native fixture execution, repeated sessions, and Unity Windows runtime remain central validation steps. Cross-compilation alone does not establish runtime acceptance.

The current own-core VFS already converts UTF-8 roots to UTF-16 and uses CreateFileW, FindFirstFileW and GetFileAttributesW. This avoids the legacy plugin's narrow Windows path limitation. A Windows import/play test in a Unicode user/install path is still required.
